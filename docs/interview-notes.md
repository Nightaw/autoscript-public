# 项目摘要

## 一句话版本

这是一个移动端音视频自动化测试框架的公开版 demo，重点展示真机场景执行之后，如何把日志和采集结果进一步解析成卡顿、分辨率等结构化质量指标。

## 稍微展开一点

这个项目我更看重的不是“写了多少自动化脚本”，而是把下面这些层次慢慢拆清楚：

1. worker 怎么接任务
2. 设备怎么抽象
3. 场景怎么编排
4. parser 怎么独立出来
5. 报告怎么统一输出

公开版里虽然没有把原项目的全部内容放进来，但这几个层次基本都能看到影子。

## 这份公开版重点保留了什么

### parser 层

- `parsers/stall/sys_log_parser.py`
- `parsers/resolution/sys_log_parser.py`
- `parsers/resolution/app_log_parser.py`

这一层主要体现的是日志解析逻辑怎么和业务脚本解耦。

### execution 层

- mock device registry
- scenario runner
- execution step model

这一层主要体现的是执行侧如何从“堆脚本”往“有结构的流程”演进。

### report 层

- JSON report
- Markdown report
- worker API response

这一层体现的是结果不是只打印在终端里，而是能进一步被别的系统消费。

## 我会怎么概括这个项目

如果要很自然地介绍，我会说：

> 我做的是一类移动端音视频自动化测试框架。除了真机控制本身，我更关注的是后面的结果提取和工程组织，比如 parser 模块化、场景执行结构化、以及质量报告输出。

## 简历描述示例

- 设计并实现移动端音视频自动化测试框架，支持 Android/iOS 真机场景化执行与结果采集。
- 抽象统一设备控制层与场景执行模型，降低多业务脚本重复开发成本。
- 建设系统日志与应用日志解析链路，支持卡顿、分辨率等关键质量指标的结构化输出。
