# 面试摘要

## 一分钟版本

我做过一类移动端音视频自动化测试框架。系统通过 worker 接口接收任务，驱动 Android/iOS 真机执行播放相关场景，采集录屏和日志，再通过日志解析或 OCR/抽帧等方式提取卡顿、分辨率等质量指标。项目的核心不是单个脚本，而是把设备控制、场景扩展和结果分析沉淀成可复用的工程框架。

## 三分钟版本

这个项目的核心可以分成三层。

第一层是服务层。它负责接收任务、做设备发现、健康检查和结果回传，本质上是一个 worker 节点。

第二层是执行层。这里会把 Android 和 iOS 的设备控制能力统一抽象，比如应用启动、录屏、手势操作、场景动作执行。这样业务脚本只需要关注“做什么场景”，不用每次都重复处理底层差异。

第三层是分析层。这里会根据日志提取播放器状态变化，并在必要时结合 OCR 或视频抽帧做补充识别，最后形成结构化结果。

这个项目适合讲的点有三个：

- 不是单脚本，而是框架化建设
- 不是单平台，而是跨端统一抽象
- 不是只跑通流程，而是把质量指标产出做成闭环

## 简历描述示例

- 设计并实现移动端音视频自动化测试框架，支持 Android/iOS 真机场景化执行与结果采集。
- 抽象统一设备控制层与场景执行模型，降低多业务脚本重复开发成本。
- 建设日志解析与 OCR/视频后处理链路，支持卡顿等关键质量指标的结构化输出。
